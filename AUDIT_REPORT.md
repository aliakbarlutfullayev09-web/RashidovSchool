## 1. Краткое резюме

**Общая оценка безопасности и готовности к production: КРИТИЧЕСКАЯ (Не готов к бою).**

Проект содержит работоспособный каркас Telegram Mini App + нескольких вариантов ботов и прямой клиентской интеграции с Supabase, однако сейчас имеет критические уязвимости аутентификации, утечку секретного токена Telegram-бота в клиентский бандл и git-историю, отсутствие серверной авторизации и RLS-политик в SQL-схеме, уязвимость SSRF на видео-эндпоинте, а также серьёзные дефекты платёжной логики (Click и Telegram Stars) и дублирование четырёх несовместимых/перекрывающихся бэкендов.

### Топ-10 проблем по приоритету

1. **Утечка `STUDENT_BOT_TOKEN` в клиентский код, бандл `admin-app` и историю Git** (`Critical`) — полный захват студенческого Telegram-бота (`admin-app/src/api/supabase.js:548,568`, `admin-app/dist/assets/index-z-HFZZ8J.js:393`, `RashidovStudio_bot/tgcloud/lib/config.js:4`, коммиты `9046858`, `6b6c613`).
2. **Полный обход аутентификации и IDOR в `user-app` и `admin-app`** (`Critical`) — `user-app` доверяет параметру `?user_id=` или откатывается на `123456789` без проверки подписи `initData`, а `admin-app` откатывается на `mockSuperadminUser` и читает роль из `start_param` (`user-app/src/App.jsx:119-128`, `admin-app/src/App.jsx:52-54`, `admin-app/src/hooks/useTelegram.js:8,28-33`).
3. **Отсутствие Row Level Security (RLS) в схеме БД и небезопасный `SECURITY DEFINER` RPC** (`Critical`) — клиентские приложения используют публичный `anon`-ключ напрямую к Supabase REST API при отсутствии политик RLS в `database/schema.sql:1-176`, а `public.increment_balance` в `backend/schema.sql:18-40` объявлена с `SECURITY DEFINER` без ограничения `REVOKE/GRANT`.
4. **Недостаточная валидация, race condition и подмена суммы в вебхуке Click** (`Critical`) — не проверяются `service_id`, `req_data.error == 0`, совпадение суммы с заказом и `merchant_prepare_id`; `SELECT` заказа выполняется вне транзакции и без `FOR UPDATE`, а `xp_to_credit` берётся как `int(req_data.amount)` (`bot/handlers/click_webhook.py:14,27-46,73,82-123`).
5. **Отсутствие идемпотентности и серверной привязки заказов в Telegram Stars** (`Critical`) — `pre_checkout_query` всегда отвечает `ok=True`, `successful_payment` не проверяет уникальность `telegram_payment_charge_id`, а эндпоинты создания инвойсов открыты без аутентификации (`user-app/api/create-invoice.js:47`, `bot/handlers/payments.py:23-68`, `backend/main.py:116-134`, `backend/student_bot.py:50-61,236-264`, `RashidovApp/tgcloud/handlers/message.js:30-40,205-233`).
6. **SSRF, спам через бота и доступ к платным видео без проверки оплаты** (`Critical`) — эндпоинты отправки видео не проверяют авторизацию и покупку урока, глушат ошибки Supabase и загружают произвольный клиентский `videoUrl` с сервера (`user-app/api/send-lesson-video.js:24-118`, `backend/main.py:137-183`).
7. **Блокирующая базовая проблема: пустой секрет вебхука не отклоняется в `backend`** (`Critical`) — `_verify_secret` при пустом `WEBHOOK_SECRET` сравнивает пустую строку с заголовком и допускает неаутентифицированные вебхуки при неполном `.env` (`backend/main.py:87-89`).
8. **Гонки и клиентская манипуляция экономикой (промокоды, заморозка стрика, ответы экзаменов)** (`High`) — промокоды и списание `10000` нейронов проверяются на клиенте; стоимость заморозки стрика расходится в 200 раз (`50` в боте vs `10000` в Mini App); правильные ответы экзаменов лежат в публичном JSON и проверяются в браузере (`user-app/src/api/supabase.js:118-186,488-514`, `bot/services/economy.py:9-18`, `user-app/src/components/ExamMistakeReview.jsx:38-45`).
9. **Неаутентифицированный AI-эндпоинт в боте с подделкой контекста и блокировкой event loop** (`High`) — `/ai` принимает любой текст с `❌` и `<!-- {...} -->` без rate limit, а `model.generate_content` вызывается синхронно в `async def`, блокируя весь бот (`bot/handlers/ai_helper.py:23-38`, `bot/services/gemini.py:37-40`).
10. **Краш-баги в боте и рассинхронизация 4 параллельных реализаций** (`High`) — `/stats` для учителей падает с `KeyError`, `/start` падает на не-текстовых сообщениях, реферальный бонус начисляется без проверки самоприглашения и дубликата, а `bot/`, `backend/`, `RashidovApp/` и `RashidovStudio_bot/` дублируют логику и используют разные схемы БД (`bot/handlers/admin.py:143-155`, `bot/handlers/start.py:99,108,118-124`).

## 2. Этап 1. Карта проекта

### Стек и архитектура
- **Фронтенд (Telegram Mini Apps, Vercel)**:
  - `user-app/` — студенческий клиент: React 18, Vite 6, TailwindCSS 3, Framer Motion, `@supabase/supabase-js` (`user-app/package.json`).
  - `admin-app/` — панель учителя и суперадмина: React 18, Vite 6, TailwindCSS 3, `@supabase/supabase-js` (`admin-app/package.json`).
  - В корне `package.json:1-16` настроены npm workspaces (`user-app`, `admin-app`).
- **Serverless API (Vercel Functions)**:
  - `user-app/api/create-invoice.js` — создание ссылки на оплату Telegram Stars.
  - `user-app/api/send-lesson-video.js` — скачивание и пересылка видео урока в чат пользователя через Telegram Bot API.
- **Бэкенды и боты (обнаружены 4 перекрывающиеся реализации!)**:
  1. `bot/` — Python 3.11, Aiogram 3.15, asyncpg, FastAPI/Uvicorn, APScheduler, `google-generativeai` (`bot/requirements.txt`, `bot/Dockerfile`, `bot/railway.toml`). Поддерживает polling, Gemini AI-разбор ошибок, Click и Telegram Stars.
  2. `backend/` — Python, FastAPI, Aiogram 3.15+, `httpx` REST-клиент к Supabase (`backend/main.py`, `backend/student_bot.py`, `backend/admin_bot.py`, `backend/supabase_client.py`). Обрабатывает вебхуки двух ботов (`student_bot` и `admin_bot`), Stars и пересылку видео.
  3. `RashidovApp/` — JavaScript/Node.js проект на `@tgcloud/cli` для студенческого бота с Telegram Stars (`RashidovApp/tgcloud/`).
  4. `RashidovStudio_bot/` — JavaScript/Node.js проект на `@tgcloud/cli` для админского бота (`RashidovStudio_bot/tgcloud/`).
- **База данных**:
  - Supabase PostgreSQL: базовая схема в `database/schema.sql:1-176` (15 таблиц: `users`, `subjects`, `subject_admins`, `courses`, `lessons`, `questions`, `progress`, `transactions`, `promo_codes`, `promo_uses`, `referrals`, `video_checkpoints`, `payments`, `duel_rooms`, `daily_quests`) + миграции/RPC в `backend/schema.sql:1-40`.

### Точки входа и внешние сервисы
- Точки входа: `user-app/src/main.jsx`, `admin-app/src/main.jsx`, `user-app/api/*.js`, `bot/main.py`, `backend/main.py`, `RashidovApp/tgcloud/endpoints/setup.js`, `RashidovStudio_bot/tgcloud/endpoints/setup.js`.
- Внешние сервисы: Supabase (PostgreSQL + REST API + Storage/media — URL `https://rcpbepcdgbxjncpxeowx.supabase.co`), Telegram Bot API (`api.telegram.org`, Mini App SDK, Stars Payments, Gifts), Click (`bot/handlers/click_webhook.py`), Google Gemini API (`bot/services/gemini.py`), хостинги Vercel и Railway.

### Основные пользовательские сценарии
1. Студент запускает `user-app` из Telegram, регистрируется/загружается из `users`, смотрит уроки (`LessonsPage.jsx`, `VideoPlayer.jsx`), отвечает на контрольные вопросы (`CheckpointModal.jsx`), проходит тесты/экзамены (`TestlarPage.jsx`, `ExamMistakeReview.jsx`), применяет промокоды, замораживает стрик и пополняет баланс нейронов через Telegram Stars или Click.
2. Администратор/учитель открывает `admin-app` или `admin_bot`, управляет предметами/курсами/уроками/видео-чекпоинтами/экзаменами, проверяет статистику и «красные зоны» (`RedZones.jsx`), генерирует промокоды, пишет студентам напрямую через Bot API (`UserList.jsx`).

- **Прогресс и закладки только локально**: прогресс просмотра видео (`user-app/src/api/supabase.js:428-486`) и сохранённые уроки `rb_saved_lessons` (`user-app/src/pages/LessonsPage.jsx:134,286`) хранятся только в `localStorage` и пропадают при смене устройства.
